## 1. 한 줄 요약

- 서버: Firebase 프로젝트 `tripnote-eb067` (Cloud Firestore + 익명 로그인)

## 2. 지켜야 할 원칙 (바꾸려면 사용자와 먼저 상의)
1. **사진은 서버에 절대 올리지 않는다.** 사진·영수증·원본은 폰(IndexedDB)에만 있고, 여행 후 "내 사진 보내기 → 사진 합치기" 파일로만 주고받는다. 개인정보 처리방침에도 그렇게 약속돼 있다.
2. **"글 함께 보기"는 글에만 적용된다.** (화면에도 '글 나만 보기 / 글 함께 보기'로 표시, 사진은 일정 상세에서 별도 카드) 한 줄 감정·일기·롤링페이퍼 쪽지는 함께 보기면 Firestore에 올라가고, 나만 보기면 폰에만 있다.
3. **오프라인에서도 돌아가야 한다.** (크루즈 바다 위) Firestore 오프라인 캐시 + 서비스워커.
4. **앱 안에 AI를 넣지 않는다.** (비용) 여행기 글 다듬기는 Claude 채팅에서. 앱의 기본 결과물은 사진첩.
5. **제휴 링크는 정직하게.** 지금은 전부 일반 링크이고 화면에 "돈을 받지 않아요"라고 표시. 파트너 번호를 넣으면 문구가 자동으로 "제휴 링크예요"로 바뀐다. 화면을 덮는 광고는 하지 않는다.
6. **아이디어는 먼저 의논하고 만든다.** 사용자가 "만들어/하자"라고 할 때만 구현.
7. **평일(월~목) 업데이트는 모아서** 퇴근할 때 한 번에 전달, 금~일은 바로 전달.

## 4. app.js 지도 (구역 표시 `/* ===== ... ===== */`)
- **맨 위 상수:** `APP`(이름), `ST`(예정/완료/보류), `CATS`(일정 분류), `PREP`(체크리스트 분류), `THEMES`, `prefs`(폰 설정), `AFF`(제휴 파트너 번호 자리), `bkURL()`(예약·쇼핑·인쇄 링크 만들기)
- **i18n:** `LANG`(auto/ko/en), `tt()` 번역 함수, MutationObserver가 화면의 한국어를 자동으로 영어로 바꿈. 사용자가 쓴 글은 번역하지 않음 (사진첩 캔버스에는 자동 번역 걸지 말 것 — 사용자 글이 깨짐)
- **IndexedDB / photos:** 사진 저장(`savePhoto`), `L`(이 폰의 로컬 상태: `L.me`, `L.photos[evId]=[{id,by,cap}]`, `L.priv`, `L.cover`, `L.imported`)
- **Firebase:** `trips/{초대코드}` 문서 + 하위 컬렉션 `events`, `expenses`, `checklist`, `notes`. 쓰기는 `w()`로 감싸 실패를 잡고, 여러 개는 `chunkedBatch()`(규칙상 한 번에 20개 제한 → 8개씩)
- **notes:** `myNote/setMyNote/flushNotes` — 함께 보기면 `notes/{key~사람id}`, 나만 보기면 `L.priv`
- **rendering:** 일정(`planHTML`, 카드 `evHTML` — 카드에 한 줄 감정 최대 3개 `.ev-moods`, 예약 도우미 버튼 `evBookHTML`), 준비(`prepHTML`, `bookCardHTML`), 예산(`budgetHTML`, 누가 냈나·정산 — 기본은 N분의 1 나눠 내기, 지출마다 `treat:true`(🎁 낸 사람이 쏨)면 나누기에서 빠지고 사람별 '쏜 금액'으로 따로 표시. 여행 문서의 `settle` 필드: `split`(기본, 정산 켜짐) / `none`(가계부, 정산 꺼짐). 새 여행 만들 때 '💸 비용을 나눠 내나요?'로 고르고(기본 나눠 내요), 예산 탭 아래 링크로 바꿈. 꺼짐이면 🎁 쏨 체크도 숨김), 여행기(`journalHTML`, 롤링페이퍼 카드)
- **photobook:** `pbPlan`(페이지 순서 계획) → `pbDraw`(캔버스에 한 쪽 그리기, 지금은 **정사각 S×S 고정**) → `pdfFromJpegs`(PDF 만들기). 페이지 종류: cover, day, photos(1~4장, 1장은 폴라로이드), cpl(Her·His 커플), 롤링페이퍼(ring/bubble/stamp/card/note), end. 스티커는 `stickerSet/placeStickers`. 인쇄 안내 `printHelpHTML`과 Blurb 가격 `BLURB`
- **detail drawer:** 일정 상세 (기록, 사진 칸 `photosHTML`, 사진 한 줄 `capModal`, 순서·대표 사진 `phEditor`)
- **settings / backup:** 메뉴 '📷 사진 모으기'. 기본은 **jpg 그대로 보내기**(`sendJpgs`: 사진 파일의 JPEG 주석(COM) 구간에 `GTJ1`+JSON {tid,ev,id,by,cap}을 넣어 공유 창으로 10장씩), 사진 합치기(`importPhotos`: jpg와 zip 둘 다 받음, `jpgMeta`로 읽음, 같은 id는 건너뜀). 파일 이름은 **영문만**(한글 파일명은 전달이 깨짐). '고급'(details.adv) 안에 zip 보내기(`exportMine`, 기록·원본 포함)와 Claude용 데이터 내보내기. 백업/복원
- **events:** 모든 버튼은 `data-act="..."` → 큰 `switch`에서 처리

## 9. 크루즈 후 (11/29 리마인드 예약됨)
사진첩 2단계(6·9장 배치, ⭐ 대표 크게, 고른 사진만, **📖 한 쪽 가득**: 사진 편집 화면에서 고른 사진은 혼자 한 쪽을 끝까지 채움(여백 없음 — 사용자 결정 11/02, 한 줄 설명은 아래에 작게, 여러 장 가능, 1장뿐인 일정도 폴라로이드 대신 가능, Blurb 재단·제본 쪽 잘림 주의. 안내: 버튼 누를 때 아래에 '인쇄할 때 가장자리가 3mm쯤 잘려요. 얼굴이 끝에 붙은 사진은 피해 주세요.' + 미리보기에서 Blurb 인쇄용일 때만 한 쪽 가득 사진에 잘리는 선을 흐린 점선으로 표시, 내보내는 PDF에는 점선 없음). **크게 그리는 규칙(11/02 확정):** ⭐ 대표는 항상 크게, 크게 나오는 건 ⭐와 📖 한 쪽 가득으로 고른 사진뿐, 나머지는 같은 크기. 지금은 3장 쪽의 첫 칸을 무조건 크게 그려서 7장(4+3)이면 ⭐는 바둑판 속 작은 칸이고 5번째가 크게, 8장(4+4)이면 ⭐도 작게, 6·9장이면 4·7번째도 크게 나옴 → 쪽 나누기(`pbPlan`의 per)와 같이 고칠 것. **4장 쪽은 항상 바둑판(11/02 확정)** — 4장에서 하나를 키우면 나머지가 4cm 남짓이라 너무 작음. ⭐는 3장 이하 쪽에서만 크게 → 쪽을 나눌 때 ⭐가 든 3장 쪽을 맨 먼저(사용자 결정: '3장 먼저' — 예: 7장 = 3+4, 8장 = 3+3+2). 정말 크게는 📖 한 쪽 가득. 편집 화면 자리 안내 한 줄은 우선순위 낮음. **표지와 단체 사진(11/02 확정):** 단체 사진은 '등장인물 소개'(사용자 의도), 표지는 여행 대표 사진 — 역할이 다름. 사진첩 만들기 화면에 '표지 사진 바꾸기'. 아무것도 안 바꾸면 단체 사진이 표지(1쪽 없음). 표지를 다른 사진으로 바꾸면 단체 사진은 1쪽(오른쪽 면, 예전에 미룬 속표지 자리) '함께한 사람들' 쪽으로 — 단체 사진 + 이름들. 단체 사진이 없으면 지금처럼 테마 색 표지. 준비 탭 카드 문구 '여행기 표지가 돼요' → '사진첩 첫 장에 함께한 사람들로 들어가요'. Blurb 뒤표지(지금: 연한 단색 + 같이가J·여행 이름)는 Blurb 미리보기·실물 보고 사진 한 장이나 롤링페이퍼 한 줄 넣을지 결정), 사진 댓글 대화, Blurb용 7×7 내보내기(엔진을 가로·세로 크기 받는 구조로), 다음 판형 후보(빈티지 일기책 / 매거진 중 하나), 예산 B-2안(지출마다 나눌 사람 고르기, 일정의 "누구랑"과 연결)
